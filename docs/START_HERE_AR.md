# ابتكر · دليل البداية للجنة التقنية

## وش فكرة الموقع؟

ابتكر مساحة لتحدّيات ابتكارية دورية داخل نادي تقنية المستقبل. نطرح مشكلة قريبة من حياة الطلاب، ويشاركون بحل مكتوب أو رسم. المجتمع يطّلع على المشاركات ويشجّع الأفكار، ويظهر ترتيب المشاركين حسب مجموع الإعجابات على حلولهم في التحدّي نفسه.

## وش بتشوفون الآن؟

الموقع متوقف مؤقتًا للصيانة. تظهر صفحة موحّدة، وتتوقف طلبات النظام ومهمة معالجة النتائج ورسائل الفائزين قبل الوصول إلى بيانات المشاركين. المشاركات والنتائج محفوظة.

المفتاح هو `siteSettings.maintenance.enabled` في `lib/site-settings.ts`. تغيير القيمة إلى `false` ثم نشر التعديل يعيد الموقع وفق التقويم الحقيقي. إرسال التهاني له مفتاح مستقل، وهو متوقف أيضًا. التفاصيل في [دليل الصيانة](maintenance.md).

## أمثلة فعلية من النظام

| التحدّي | تجربة المشارك |
| --- | --- |
| إلغاء الاشتراك… بدون دوّامة. | اختيار زاوية تفكير ثم كتابة حل يحسّن تجربة الإلغاء |
| جرّبها… قبل ما تشتريها. | اقتراح طريقة لتجربة فائدة منتج قبل شرائه |
| لمبة ولعت… فهمتها؟ | اختيار رمز تحذير من السيارة وإعادة تصميمه بالرسم |
| رسالة على علبة. يفهمها أي أحد. | بدء مؤقت يكشف مهمة عشوائية، ثم رسم رمز تغليف خلال دقيقتين، مع تخطيين كحد أقصى |

حُذفت صفحات التجارب القديمة، ومنها الكوب واللعبة ثلاثية الأبعاد، من النسخة الحالية. بقيت تجارب التحدّيات الرسمية ومشاركاتها ونتائجها.

## أهم نقطة في النقل

**تغيير نص السؤال لا يكفي دائمًا.** بعض الأسابيع تحتاج كتابة، وأخرى تحتاج رسمًا، وأخرى مؤقتًا ومهمة لا تظهر إلا بعد البدء. الموقع الحالي يجمع هيكلًا مشتركًا مع واجهة وتفاعل يناسبان نوع التحدّي.

المطلوب الاتفاق عليه مع فريق البوابة: كيف نضيف واجهة أسبوعية جديدة ونختبرها وننشرها؟ ومن ينفّذ التعديل التقني؟ مسؤول المحتوى يستطيع إعداد السؤال والقواعد، لكن التفاعلات الجديدة تحتاج عملًا تقنيًا ما لم توفّر البوابة أدوات تدعمها.

## وين ألقى كل شيء؟

| المكان | وش فيه؟ |
| --- | --- |
| `app/innovation-app.tsx` | واجهة الموقع الرئيسية والتنقل والمجتمع والنتائج والملف الشخصي |
| `lib/weekly.ts` | تعريف الأسابيع ومواعيدها ونوع مشاركة كل أسبوع |
| `app/weekly-challenge-view.tsx` | العرض المشترك للتحدّيات النصية ورموز السيارة |
| `app/packaging-challenge.tsx` و`lib/packaging-game.ts` | تجربة رسم رموز التغليف بالمؤقت |
| `app/api/community/route.ts` | التحقق من المستخدم وحفظ المشاركات والتعليقات والتصويت |
| `lib/community-read.ts` | تحميل المشاركات والنتائج والتصفية والصفحات |
| `lib/weekly-db.ts` | حساب الترتيب وحفظ النتيجة النهائية |
| `lib/weekly-email.ts` | اختيار مستحقي التهنئة وإدارة الإرسال وإعادة المحاولة |
| `lib/site-settings.ts` و`lib/maintenance.ts` | مفتاح الصيانة وإيقاف الطلبات ومهمة الخادم |
| `tests/` | اختبارات ببيانات تجريبية، بعيدًا عن مشاركات الطلاب الحقيقية |

## وين تُحفظ البيانات؟

- **Supabase Auth:** حساب المستخدم والتحقق من تسجيل الدخول بالبريد.
- **Cloudflare D1:** اسم العرض والمشاركات والرسومات والتعليقات والإعجابات والنتائج. بيانات طابور رسائل الفائزين خاصة بالخادم.
- **متصفح المستخدم:** الجلسة والمسودات ومحاولات الرسم المحلية.
- **GitHub:** الكود وشرح النظام وتاريخ التعديلات. ليس لوحة لإدارة حسابات الطلاب أو قاعدة بياناتهم.

## كلمات بتتكرر في الملفات

| المصطلح | معناه هنا |
| --- | --- |
| Repository / مستودع | مجلد المشروع مع تاريخ تعديلاته |
| Commit | نسخة محفوظة من مجموعة تعديلات |
| Branch | مسار منفصل لتطوير تعديلات قبل دمجها |
| API | مسار يتواصل معه المتصفح لقراءة البيانات أو حفظها |
| Migration | ملف يغيّر بنية قاعدة البيانات أو ينفّذ تحويلًا مسجلًا مرة واحدة |
| Cron | مهمة يشغّلها الخادم دوريًا، كل خمس دقائق في هذا المشروع |
| Frozen result | نتيجة نهائية محفوظة بعد إغلاق التصويت |
| Idempotency | إعادة الطلب لا تنشئ مشاركة أو رسالة إضافية لنفس العملية |
| Secret | قيمة وصول خاصة بالخادم، مثل مفتاح إرسال البريد |

ابدؤوا بهذا الملف، ثم [خريطة النظام](architecture.md) و[نقاط نقل البوابة](portal-handoff.md). مراجعة المستودع لا تحتاج دمج تعديلات إلى `main` أو تشغيل أوامر نشر.
